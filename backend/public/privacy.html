Privacy Policy — Usage Monitor

Last updated: July 22, 2026

Usage Monitor is not affiliated with, endorsed by, or sponsored by Anthropic. It is an independent, unofficial tool that reads usage information from your own Claude.ai account, using your own browser session.

What this extension reads

Usage Monitor reads two things from Claude.ai, only when you open the extension's popup or click "Check Now" (or, if you've separately enabled the optional Advanced background-checking mode in settings, on a periodic timer):

  1. Your organization ID — read from the lastActiveOrg cookie already set by claude.ai in your browser. This is an identifier, not a secret — it is not your password or session key.
  2. Your usage percentages — fetched from Claude.ai's own usage endpoint, using your browser's existing logged-in session (the same way the Claude.ai website itself shows you this information when you visit your account settings).

Usage Monitor never reads, stores, or transmits your Claude.ai password, session key, or any other authentication credential. Your browser attaches your existing login automatically when fetching your own usage data; the extension's code never has access to that credential directly.

What this extension does NOT read

Usage Monitor does not read your conversations, prompts, or any content you send to or receive from Claude. It reads only the account-level usage percentage data described above.

Where your data goes

Nowhere, by default, beyond your own browser's local storage — unless you configure one of the following optional features yourself:

  • Alert channels (Discord, Telegram, Slack): if you provide a webhook URL, bot token, or similar credential in settings, a short text message (your current usage percentage and which threshold was crossed) is sent to that channel when you've configured an alert threshold. These credentials and destinations are entirely of your own choosing — Usage Monitor does not have or use any of its own.
  • Optional self-hosted dashboard: if you choose to run the optional backend (on your own server/hardware) and enter its address in settings, usage snapshots are sent there so you can view your usage history from other devices. This is your own server; the developers of Usage Monitor have no access to it or the data stored there.

The developers of Usage Monitor do not receive, store, or have access to any of your usage data, credentials, or alert-channel information. There is no central server operated by Usage Monitor's developers that your data passes through.

Permissions this extension requests, and why

  • Storage — to save your settings and the most recent usage snapshot locally in your browser.
  • Cookies (for claude.ai only) — to read the lastActiveOrg cookie described above.
  • Alarms — used only if you enable the optional Advanced background-checking mode; otherwise unused.
  • Host permissions for claude.ai, discord.com, api.telegram.org, and hooks.slack.com — to fetch your usage data and to send alerts to the channels you configure.
  • Optional host permission for a self-hosted backend address — granted only for the specific address you enter, only if you choose to use the optional dashboard feature.

Data retention

Usage snapshots and settings are stored locally in your browser via chrome.storage.local, and (only if you've configured it) in your own self-hosted backend. Uninstalling the extension removes its local storage. If you've used the optional backend, data there persists until you delete it yourself, since it lives on your own server.

Changes to this policy

If this policy changes, the updated version will be posted here with a revised "last updated" date.
